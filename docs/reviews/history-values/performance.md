For H events, at most3H references are examined in payload/result/error order;
fetch deduplication keeps first occurrence before filtering binary, nonempty
refs at65535 bytes. ValueStore separately recognizes actual p/r/e/s/n key grammar,
including canonical version/name forms. A length-valid non-flow ref receives a
missing slot. No payload read is justified merely by accepting arbitrary bytes
as a reference, and the neighboring4096 option bound is not this path's bound.

At most six field keys per event are added; errors/omission/missing branches do
not clear older values, errors or flags. Stored byte count includes the FSV2
wrapper; type1 strips one header only, type2 decodes safe ETF, and unknown or

Allocation/resource failure must not be silently translated into corrupt data.

provenance. Only eligible PRIMARY nils trigger fallback; storage failure does
not. Actual source fallback routes by reference, reads real LMDB/cold/history/

field, not missing. File-ref omission uses validated stored size without payload
materialization; hot bytes and LMDB fallback may already materialize an oversized
value before HistoryValues omits it. max_bytes therefore limits returned stored

### Concrete next ownership and implementation decision

Existing Rust blob/query/projection files are reservations, and genuine state
point reads expose core record/policy/control/outcome data, not a raw value
catalog. Reduced FWSH history lacks arbitrary fields and payload/result/error
references. Neither it nor the private closed-policy ETF/FWPV representation is
complete successful hydration. The latter's depth64/span4096 profile must not
silently become generic source invalidity.

I support ARCH's next named codec consultation at existing value.rs and proposed
value/original_flow responsibility children, before the later actual ports/blob,
storage/blob and application history orchestration selections. The proposed
boundary moves Vec<u8> into an OriginalValueDocument and accepts a borrowed
explicit OriginalValueContext plus a separate resource profile. It returns a
flat typed node/edge document whose byte spans address its own moved buffers.
Views borrow that document. It must not return slices into temporary owned read
Vecs, use a self-referential struct, clone every leaf, or recursively own an
unbounded ETF tree whose parse/equality/drop can exhaust the native stack.
Exact names/fields/methods/private workers are proposals until ARCH records them.

Before final arenas are filled, syntax/count validation must check offsets,
length/arity multiplication, actual nodes/edges and needed work-stack slots,
including STRING expansion and arbitrary-precision magnitude storage. Counting
itself needs prospectively bounded/fallible scratch; there is no free recursive
preflight. Then reserve the actual selected owner arrays fallibly and fill using
IDs/ranges. Keep invalid wire, unavailable local profile/context, explicit
operational limits and real TryReserveError distinct. No arbitrary input/depth/
ref cap is introduced as source corruption. Adopted limits are honest operational
profiles, and unsupported profiles remain incomplete in the parity ledger.

Semantic map uniqueness is an additional real workload. Normalize equivalent
integer, atom and list spellings; preserve finite float bits and compare compound
keys structurally, including order-independent maps. A linear byte scanner does
not prove linear duplicate detection. A naive all-pairs key scan can be quadratic,
and repeated compound comparisons add traversal work. ARCH must select the exact
comparison/indexing and checked work accounting before claiming complexity.
Encoded owners, count/stack scratch and result arenas have separate live ranges;
drop retired scratch when possible. Moving one backing buffer avoids a whole
payload clone but may retain unused bytes/capacity until the document dies.
Stable fetch dedup is not permission to change per-occurrence source decoding or
cache across changing safe profiles.

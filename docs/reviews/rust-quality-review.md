## Findings for the main architecture author

1. **Resolve claim strategy before M1, not after a consensus implementation.** Candidate revisions prove candidate freshness, but cannot prove that an omitted higher-priority/earlier FIFO record does not exist. A bounded leader candidate set needs an authoritative ordered-prefix/range validation contract, including phantom insertions and changes to ordering keys. Recommend selection from authoritative replicated indexes at apply for the first design. If bounded scanning can yield fewer results, define continuation and empty/partial reply semantics explicitly. A projected candidate set must never certify eligibility. Architecture's two alternative strategies remain an unresolved correctness decision.
2. **Separate client digest from prepared-entry digest.** `CommandEnvelope` now proposes a stable digest for request-ID reuse. Preparation adds leader time, IDs and candidates; retry on a new leader can change them. Digest the canonical client intent for idempotency comparison, and separately identify the immutable prepared committed entry. Check persisted request identity/outcome before recomputing lease, retry, or revision preconditions during replay/retry. Otherwise a successfully applied command can later be rejected as stale, violating original-outcome replay. A deterministic rejection also needs an explicitly defined durable deduplication outcome and applied checkpoint.
3. **Do not treat storage failure as `DomainError`.** State-precondition rejection is deterministic; disk-full, corrupt authoritative reads and transaction failure are node/storage failures. They must stop or retry ordered apply under the selected Raft contract, without advancing last-applied or persisting a fabricated business rejection. Define how a transition view, decision, transaction and next apply share one consistent authoritative version. Read errors must not become an empty state view.
4. **Trait ownership can be settled without another bridge crate.** Keep storage-neutral read/transaction/log/snapshot contracts in ports. A local wrapper type in consensus can hold those ports and implement the external OpenRaft traits, with node supplying storage implementations. A foreign trait cannot simply be implemented for a foreign storage type in node without a local wrapper. Recommend this ownership as the initial design, reserving an outer bridge crate only for a demonstrated API constraint. Do not duplicate workflow rules in node-owned glue. Validate against the selected OpenRaft API rather than inventing its exact signatures now.
5. **Canonical allowlist reconciled.** Quality note now matches API → types/domain/ports/application and worker → types/domain/ports. `WorkflowClientPort` resolves the prior worker/application mismatch. These are permitted dependencies, not mandatory imports. API may use domain values for conversion and ports for read contracts; all command/query orchestration still delegates to application. Worker uses a distinct client capability and cannot access ConsensusPort or authoritative storage merely because both live in ports. Add item/module capability checks and private constructors/wiring; crate graph checks alone cannot enforce this. Consider split ports modules before adding another crate.
6. **Keep the eleven-crate list provisional.** Domain isolation and adapter separation are justified. Types/ports/application have distinct policies, so do not merge just to reduce a count. Architecture-tests may instead be a dev-only test package/target; a separate crate is useful only for workspace tooling. A separate HTTP worker adapter is a later option, not an MVP requirement. Measure boundary enforcement and public API complexity in M0, not crate count alone.
7. **Cache-derived-only is accepted, with one qualification.** The architecture correctly removes cache authority over lease/FIFO/eligibility/auth. Correctness-critical materialized indexes are durably maintained authoritative selection structures even if mathematically derived; they differ from disposable cache/projection state. Specify this distinction explicitly so an implementer does not rebuild or consult an asynchronous projection inside apply. No cache pointer/guard may escape through a port or across `.await`; owned versioned values and cold-cache fallback are required.
8. **Make scope gates visible in the main plan.** Workflow note explicitly identifies governance, effects and durable steps as unclosed scope. Main architecture/plan should list these, assign parity dispositions, and reject unsupported commands. M5 breadth does not currently name them; omission must not imply they were deliberately dropped or that full parity has been reached.
